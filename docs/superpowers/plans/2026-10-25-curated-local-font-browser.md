# Curated Local Font Browser Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a curated, locally served font browser that helps poster makers find a typeface, preview emphasis, and carry that choice into their prompt.

**Architecture:** Keep the current Fontsource package and data-catalog pattern. Expand the catalog with measured popular families and explicit category, popularity, weight, and italic support metadata. Add backward-compatible recipe preferences and compile them into prompt typography descriptors. Replace the static specimen grid with an accessible searchable dropdown and live preview; locally bundle the website shell faces too.

**Tech Stack:** Astro 7, TypeScript, vanilla browser-side composer, Fontsource, Tailwind CSS 4, daisyUI 5.

**Spec:** `docs/superpowers/specs/2026-10-25-curated-local-font-browser-design.md`

## Global Constraints

- Keep an intentionally curated catalog, adding widely used families that complement the existing display and editorial range: Roboto, Open Sans, Montserrat, and Poppins.
- Bundle font files and styles through pinned Fontsource packages. Preserve the app's local-first behavior and avoid a runtime font catalog API.
- Make it easy to search and filter by useful design categories such as sans, serif, condensed/display, and mono.
- Let users compare the specimen in regular, bold, and italic treatments, with a representative poster line that updates immediately.
- Carry selected family and supported emphasis into the compiled prompt. Make clear that image models receive a type description, not the actual font file; exact lettering can be typeset after generation.
- Replace the site shell's Bunny Fonts stylesheet request with locally bundled Heebo and Signika faces while preserving their configured roles.
- Keep existing recipe import/export compatibility. New emphasis fields must have safe defaults when older saved recipes are loaded.
- Do not add user uploads, remote discovery, an account, or an external font API.
- Do not add or run tests in this implementation unless the user requests them; use build/type checks and manual interaction review for verification.

## Review Focus

- **Older stored or imported recipes:** missing emphasis fields retain the current default selection and compile without changing their other values.
- **Font families without bold or italic files:** unavailable modifiers are visibly disabled and cannot be applied through the picker.
- **Combined search and category filtering:** results satisfy both controls, and zero matches show a clear-search recovery action.
- **A style that owns its lettering:** compiled prompt behavior continues to explain that the style lettering takes precedence over a selected font.
- **Local-only font delivery:** built app font CSS and page head contain no Bunny Fonts request for the font assets handled by this feature.
